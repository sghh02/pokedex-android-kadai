# モバイルアプリ開発 最終課題

カントー地方のポケモン図鑑アプリを **Android ネイティブ（Kotlin + Jetpack Compose）** で実装します。
全16 Issue、4週間で完成する構成です。

上から順に読んでいけば、何を作るのか、どう作るのか、どこから手をつけるのかが分かります。

## 何を作るのか

PokeAPI からカントー地方の151匹を取得して、一覧と詳細を表示する図鑑アプリです。
一度取得したデータは端末に保存し、電波がなくても見られるようにします。

なぜ作るのか、誰のためのものか、どこまでを対象にするのかは
[01 要件定義](docs/01_要件定義.md) に書いてあります。

## どう作るのか

[02 基本設計](docs/02_基本設計.md) が全体の骨組みです。
画面の一覧と遷移図、PokeAPI とのやりとり、テーブル構成といった「形」が決まります。

そのうえで [03 詳細設計](docs/03_詳細設計.md) が、機能ごとのシーケンス図と
Kotlin の実装例まで踏み込みます。分量があるので、実装する機能のところだけ読めば十分です。

## 今回どこまで作るのか

[04 実装仕様](docs/04_実装仕様.md) が課題としての範囲を決めます。
必須機能と加点機能、実装の共通ルール、技術スタック、評価基準の配点、4週間のスケジュール。
迷ったらこの文書が基準です。

Kotlin / Jetpack Compose / ViewModel + StateFlow / Room / Retrofit / Coil / Navigation Compose、
`minSdk` は 26（Android 8.0）を使います。

## 手を動かす

[05 環境構築ガイド](docs/05_環境構築ガイド.md) に沿って、Fork から最初のビルドまで通します。
リポジトリを Fork して clone し、プロジェクトを作り、依存を追加して、PokeAPI に繋がるところまで。
ここまでで Issue `#1` と `#2` が終わります。

## 実装する

あとは [Issues](../../issues) を `#1` から順に進めるだけです。

1. Issue ごとにブランチを切る
2. 実装する
3. プルリクエストを作成する
4. メンターに PR の URL を添えてレビューを依頼する
5. LGTM をもらったら、その Issue は完了

各 Issue には受け入れ条件が付いています。すべて満たしてからレビューを依頼してください。

| 週 | Issue | やること |
| --- | --- | --- |
| 1週目 | #1 〜 #2 | 環境構築 |
| 2週目 | #3 〜 #5 | データレイヤー |
| 3週目 | #6 〜 #10 | UIレイヤー（ここまでで必須要件を満たす） |
| 4週目 | #11 〜 #16 | 機能拡張・提出 |

`#1` 〜 `#10` が必須要件（70点）、`#11` 〜 `#14` が加点要件（+30点）、
`#15` がボーナス、`#16` が提出物です。
