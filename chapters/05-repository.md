# Issue #5: PokemonRepository 実装

**この課題の山場です。** API とローカルDBの使い分けを1箇所に集約し、画面側から隠します。

考え方は「**DBが唯一の情報源**（single source of truth）」。画面は常に DB を見ます。
API はDBを更新するためだけに使い、更新されれば `Flow` を通じて画面に自動で伝わります。
ここが腹落ちすると、以降の画面の章が一気に楽になります。2〜3日かかって想定どおりです。

## 1. この章でやること

- 一覧取得は常に DB の `Flow` を返す
- `refresh()` で API から取得して DB に保存する。画面の更新は `Flow` 任せにする
- 詳細情報は API から取得し、取得できた分をキャッシュする
- API 障害時は最大3回まで再試行する（1件ごとの待機は短いバックオフ）
- 通信失敗時は例外を投げず、`Result` などの結果型で成否を返す

## 3. つまずきどころ

- **要件定義の「30秒間隔」を1匹ごとの待機だと読み違えないこと。** あれはユーザーが再試行できるようになるまでの間隔です。1匹ごとに30秒待つと151匹で75分かかります
- `refresh()` が画面に直接結果を返す作りにしないこと。DB を更新すれば `Flow` が流れます。二重で通知すると、同じデータで2回描画されます
- 通信失敗を例外で投げ上げると、呼び出し側が全部 try-catch だらけになります。結果型で返してください
- テストを書くために、API と DAO は**インターフェース越しに**受け取る作りにしておくこと
